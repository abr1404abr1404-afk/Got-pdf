# رؤية المنتج والمعمارية المستهدفة — الفلقي PDF

**الرؤية:** بناء منصة موحدة لإنشاء المستندات وقراءتها وفهمها وتحريرها وتحويلها ومشاركتها، بحيث ينجز المستخدم سير عمله داخل مكان واحد دون الحاجة إلى التنقل بين أدوات متفرقة.

**المبدأ الحاكم:** عمق وجودة كل أداة أهم من عدد الأدوات. لا تُعلن أي قدرة على أنها مكتملة حتى تجتاز اختبارات جودة وظيفية وأمنية وأدائية وتجربة استخدام.

## ما معنى أن تكون المنصة شاملة؟

نغطي دورة حياة المستند كاملة:
1. الإدخال: PDF، صور، مسح بالكاميرا، ملفات Office، وملفات نصية.
2. الفهم: OCR، اكتشاف التخطيط والجداول والصور والحقول، واستخراج المحتوى.
3. الإنشاء: إنشاء PDF، صفحات، نماذج، تعليقات، ورسومات.
4. التحرير: النصوص، الصور النقطية، الرسومات المتجهة، الصفحات، الحقول والبيانات الوصفية.
5. التحويل: Word وExcel وPowerPoint وPDF/A وصيغ الصور والنصوص، مع تقارير جودة.
6. المراجعة: مقارنة نسخ، تتبع التغييرات، التعليقات، والتحقق من الجودة.
7. الحماية: كلمات المرور، الصلاحيات، الحجب الحقيقي، التحقق من الملفات، والخصوصية.
8. المشاركة والتسليم: تنزيل، طباعة، QR، تخزين يختاره المستخدم، وروابط مشاركة آمنة.
9. الأتمتة: عمليات متعددة الخطوات وقوالب قابلة لإعادة الاستخدام.

## معايير اكتمال كل أداة

كل أداة لها بطاقة جودة موحدة:
- صحة النتيجة: مجموعة عينات مرجعية وقياسات قابلة للتكرار.
- التغطية: الحالات الأساسية والاستثنائية والملفات الكبيرة واللغات المدعومة.
- سلامة الأصل: عدم إتلاف الملف الأصلي عند الفشل؛ إنشاء نسخة جديدة عند التعديل.
- قابلية التراجع: Undo/Redo أو مسار استعادة واضح عندما يكون ذلك ممكنًا.
- الأداء: زمن المعالجة والذاكرة وحدود الحجم وعدد الصفحات.
- الأمان والخصوصية: تحديد ما يعالج محليًا وما يرسل إلى الخادم أو مزود خارجي.
- سهولة الاستخدام: خطوات قليلة، رسائل مفهومة، دعم لوحة المفاتيح واللمس وإمكانية الوصول.
- الاختبارات: وحدات، تكامل، ملفات واقعية منزوعة البيانات الحساسة، واختبار جوال.

لا يكفي وجود زر أو نجاح حالة بسيطة. يجب أن نعرف بدقة الحالات التي تدعمها الأداة والحالات التي لا تدعمها.

## المعمارية: اختيار اللغة حسب المهمة

لا نعيد كتابة المشروع كاملًا لمجرد استخدام لغات أكثر. نحتفظ بالواجهة الحالية وFastAPI/Python حيث يقدمان قيمة، ونضيف خدمات مستقلة فقط عندما تثبت الحاجة.

| الطبقة | تقنية مرشحة | الاستخدام |
|---|---|---|
| واجهة الويب وPWA | TypeScript مع مكونات واجهة تدريجية | واجهة موحدة، إدارة الحالة، الأدوات التفاعلية، والعمل المحلي |
| API وتنسيق العمليات | Python + FastAPI | إدارة الجلسات، التحقق، تنسيق المهام، وربط محركات PDF/OCR |
| معالجة PDF | PyMuPDF ومكتبات متخصصة مع مراجعة التراخيص | الصفحات، النصوص، الحجب، الصور، البيانات الوصفية والتحويل |
| OCR والتخطيط | PaddleOCR/Tesseract حاليًا، مع تقييم نماذج تخطيط/رؤية إضافية | اكتشاف مناطق النص، اتجاه القراءة، الجداول، الخطوط واللغات |
| مهام ثقيلة اختيارية | خدمة عامل مستقلة بلغة/بيئة مناسبة بعد القياس | تحويلات كبيرة أو نماذج AI أو معالجة GPU عند الحاجة |
| تخزين مؤقت/طوابير | Redis أو بديل مُدار عند الحاجة | المهام الطويلة، الحالة، تحديد المعدل، ومنع تحميل API |
| التخزين | محلي أولًا أو موفر يختاره المستخدم، مع تخزين خادمي مؤقت عند الضرورة | حفظ الملفات مع سياسة حذف ومدة احتفاظ معلنة |

**قواعد المعمارية:**
- لا نضيف خدمة أو لغة جديدة دون سبب مقاس واختبار يثبت فائدتها.
- كل خدمة لها API وعقد بيانات واضح، حدود للملفات والوقت والذاكرة، وسجل أخطاء لا يكشف محتوى المستند.
- المعالجة المحلية هي الخيار الأول عندما تكون ممكنة وآمنة.
- لا نرسل ملفات المستخدم إلى AI أو خدمة خارجية دون موافقة صريحة وشرح واضح.
- نعزل الخدمات الاختيارية حتى لا يؤدي تعطل محرك واحد إلى تعطل بقية المنصة.
- نراجع تراخيص المكتبات، خاصة المكتبات ذات تراخيص AGPL أو الشروط التجارية، قبل أي إطلاق تجاري.
- لا نضع أسرار API في الواجهة أو المستودع.

## خارطة الطريق

### المرحلة 1 — تثبيت الجودة والقياس
- اختبارات مرجعية للـ OCR حسب نوع الخط واللغة والتخطيط.
- اختبارات تحويل Word/Excel مع مقارنة التخطيط والجداول واتجاه RTL.
- مراجعة سلامة تحرير الصور والحجب والملفات المحمية.
- مراقبة زمن المعالجة والذاكرة وحجم الملفات والأخطاء.
- اختبارات فعلية على Safari iOS وChrome Android وأجهزة سطح المكتب.

### المرحلة 2 — إكمال أدوات المستند الأساسية
- تحرير النص الأصلي مع الحفاظ على التخطيط حيث تسمح بنية PDF.
- تحرير متقدم للصور والرسومات المتجهة.
- مقارنة ملفين نصيًا وبصريًا.
- إنشاء النماذج وتعبئتها والتحقق من حقولها.
- أدوات صفحات ومعالجة جماعية قوية.

### المرحلة 3 — الفهم الذكي للمستند
- OCR متعدد المراحل: كشف النص، تصنيف نوعه، قراءة النص، ترتيب القراءة، ثم مراجعة.
- دعم خاص للخطوط المزخرفة والخط العربي الفني وفق نتائج مجموعة اختبار حقيقية.
- فهم الجداول والنماذج والفواتير والمستندات الطويلة.
- تلخيص واستخراج بيانات بإحالات إلى صفحات ومناطق المصدر.
- إظهار درجة الثقة وطلب مراجعة بشرية عند عدم اليقين بدل اختلاق نتيجة.

### المرحلة 4 — منصة سير عمل موحدة
- مهام متعددة الخطوات قابلة للحفظ.
- سجل إصدارات ومراجعات وتعليقات.
- إدارة مشاركة وصلاحيات وتكاملات تخزين.
- واجهات API وتكاملات للمؤسسات عند الحاجة.
- مراقبة تشغيلية ودعم واستعادة موثوقة.

## لوحة قياس النجاح

نقيس التقدم بمؤشرات فعلية لا بعدد الميزات:
- دقة OCR (CER/WER) حسب فئة الخط واللغة.
- نسبة نجاح التحويل مع سلامة الجداول وترتيب القراءة والتنسيق.
- نسبة العمليات المكتملة دون إفساد الأصل.
- زمن المعالجة واستهلاك الذاكرة حسب حجم الملف.
- نسبة الأخطاء التي يمكن استعادتها دون فقد العمل.
- نجاح المهام من أول محاولة على الهاتف وسطح المكتب.
- نسبة المهام التي ينجزها المستخدم داخل الفلقي دون الحاجة إلى خدمة خارجية أخرى.

## تعريف النجاح

الطموح هو أن يصبح الفلقي من أقوى المنصات وأكثرها اكتمالًا وموثوقية في فئته. لا يمكن ضمان أن لا تضاهيه أي منصة أخرى، لكن يمكن بناء تفوق قابل للقياس في تجربة عربية ممتازة، وتكامل الأدوات، ودقة النتائج، والخصوصية، وسرعة إنجاز العمل.
