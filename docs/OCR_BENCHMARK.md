# مختبر قياس جودة OCR

يستخدم هذا المختبر دوال المعالجة والتعرّف الفعلية من `main.py`، ويقارن Tesseract وPaddleOCR والمسار الهجين على صور ذات نص مرجعي مكتوب يدويًا.

## لماذا نحتاجه؟

وجود دعم للغة العربية لا يثبت الدقة. نحتاج مجموعة عينات متنوعة ومصرّح باستخدامها، مع نص مرجعي دقيق، ثم نقيس:
- **CER**: معدل خطأ الحروف؛ الأقل أفضل.
- **WER**: معدل خطأ الكلمات؛ الأقل أفضل.
- **الزمن** لكل صورة، وعدد العينات الناجحة والفاشلة.

## إعداد مجموعة القياس

1. أنشئ مجلدًا مثل `benchmarks/my-arabic-set/images/`.
2. أضف صورًا اصطناعية أو عامة أو لديك موافقة واضحة على استخدامها. لا تستخدم هويات أو سجلات أو مستندات شخصية.
3. انسخ `manifest.example.json` إلى `manifest.json`.
4. لكل صورة، اكتب النص الظاهر فيها بدقة في `reference`. حافظ على ترتيب القراءة الطبيعي، ولا تخمّن الكلمات غير المقروءة.
5. اجعل كل صورة قصيرة نسبيًا، وضمّن تنوعًا في جودة التصوير، والخطوط، والتباين، والميلان، والنص العربي المختلط بالإنجليزي والأرقام.

## التشغيل

شغّل من بيئة الخادم التي تحتوي على اعتمادات المشروع:

```bash
python tools/ocr_benchmark.py --manifest benchmarks/my-arabic-set/manifest.json
```

لتشغيل Tesseract فقط:

```bash
python tools/ocr_benchmark.py --manifest benchmarks/my-arabic-set/manifest.json --engines tesseract
```

ولتحديد مكان التقرير:

```bash
python tools/ocr_benchmark.py --manifest benchmarks/my-arabic-set/manifest.json --output benchmarks/my-arabic-set/report.json
```

## تفسير النتائج

- قارن CER وWER على **نفس الصور والنصوص المرجعية**.
- لا تعتمد على المتوسط وحده؛ راجع نتائج كل عينة وأخطاء أسماء الأشخاص والأرقام والتواريخ.
- سجّل نسخة المحرك وإعدادات البيئة عند مشاركة النتائج.
- لا تعلن أن محركًا أفضل قبل توفر مجموعة متنوعة وكافية؛ العينة الصغيرة لا تمثل جميع المستندات.
- في المقارنة الحالية، Tesseract يعمل بإعداد PSM 11، وPaddleOCR يستخدم إعداداته الحالية، وHybrid يستخدم مسار التطبيق الكامل. لذلك التقرير يقيس إعدادات المشروع الحالية، لا أقصى أداء ممكن لكل محرك.

البرنامج لا يرفق مجموعة بيانات حقيقية تلقائيًا؛ يجب إضافة عينات مرجعية مصرح بها قبل صدور نتائج دقة فعلية.


## تصنيف العينات (مهم للخطوط المزخرفة)

أضف خاصية `category` اختيارية لكل عينة في manifest. سيصدر التقرير متوسط CER/WER والزمن لكل محرك **داخل كل فئة**، حتى لا تخفي نتيجة الخطوط المطبوعة الجيدة ضعف التعرف على الخطوط المزخرفة.

فئات مقترحة:
- `printed_arabic`: نص عربي مطبوع عادي.
- `decorative_font`: كتابة بخط مزخرف أو عرضي.
- `calligraphy`: خط عربي فني/متصل.
- `outlined_or_shadowed`: حروف بحدود أو ظلال.
- `textured_background`: كتابة فوق خلفية مزخرفة أو صورة.
- `low_contrast`: تباين ضعيف.
- `mixed_arabic_latin`: عربي وإنجليزي وأرقام في الصورة.
- `handwriting`: كتابة يدوية.

مثال:
```json
{
  "id": "decorative-01",
  "image": "images/decorative-01.png",
  "reference": "النص الصحيح كما يظهر في الصورة",
  "language": "ara",
  "category": "decorative_font"
}
```

لا تخلط بين **اكتشاف منطقة الكتابة** و**قراءة الحروف**. عند فشل عينة مزخرفة، سجّل هل لم تُكتشف المنطقة أصلًا أم اكتُشفت مع نص خاطئ. هذا التصنيف يساعد على اختيار العلاج المناسب بدل زيادة المعالجة عشوائيًا.


## سلامة ملف manifest

يتحقق المختبر قبل بدء OCR من أن كل عينة كائن صالح، وأن مسار الصورة نسبي ويبقى بعد حلّ الروابط داخل مجلد ملف manifest، وأن النص المرجعي غير فارغ ومعرّفات العينات غير مكررة. هذا يمنع بالخطأ قراءة ملفات خارج مجموعة القياس، ويجعل أخطاء إعداد البيانات تظهر قبل استهلاك موارد OCR.


## حدود السلامة وقياس المسار

- يرفض المختبر أكثر من 500 عينة، والمسارات المطلقة أو التي تخرج من مجلد manifest بعد حل الروابط الرمزية.
- الحد الأقصى للصورة الواحدة 25 MB، والنص المرجعي 100,000 محرف.
- فشل محرك واحد لا يصنّف العينة فاشلة إذا أعاد محرك احتياطي نصًا؛ يسجل الخطأ الجزئي في `partial_engine_errors`.
- نتائج التحويل إلى Word تتضمن الآن تشابه ترتيب الكلمات بجانب التغطية والدقة. يُحسب هذا المؤشر للوثائق التي لا تتجاوز 3,000 كلمة مصدر وناتج، لتجنب استهلاك CPU غير محدود؛ وما يتجاوز ذلك يعرض القيمة `null`.
