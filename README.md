# الفلقي PDF — محرر PDF مع OCR هجين

هذا المستودع يحتوي على واجهة محرر PDF الحالية وخادم OCR اختياري يعمل باستخدام Python. تم الإبقاء على ملفات الواجهة في جذر المستودع؛ لا توجد مجلدات `frontend/` أو `backend/` في البنية الحالية.

## بنية المستودع

```text
Got-pdf/
├── index.html          # واجهة محرر PDF
├── config.js           # إعدادات API وتهيئة OAuth العامة الاختيارية
├── main.py             # خادم FastAPI وOCR ومساعد المستندات
├── pdf_tools.py        # تحسين PDF دون فقد جودة
├── requirements.txt    # اعتمادات Python
├── Dockerfile          # بناء خادم OCR
├── render.yaml         # إعداد نشر Render
├── PLAN.md             # خطة التطوير
├── SHARING_AND_ROADMAP.md # مواصفات مشاركة Drive/QR وخطة الحسابات
└── README.md
```

## مشاركة PDF عبر Google Drive وQR

أُضيفت واجهة مشاركة اختيارية في المحرر. تنشئ نسخة PDF النهائية وترفعها مباشرة من المتصفح إلى مجلد «الفلقي PDF» في Drive، ثم تولّد QR للرابط. تبقى بقية الأدوات متاحة دون تسجيل، ولا يُرفع شيء تلقائيًا. الميزة تتطلب إعداد Google Cloud وكتابة OAuth Web Client ID العام في `ALFALQI_GOOGLE_CLIENT_ID` داخل `config.js`. لا تضع Client Secret في الواجهة أو المستودع. مشاركة «أي شخص لديه الرابط» غير مفعلة افتراضيًا وتحتاج اختيار المستخدم. التفاصيل في [SHARING_AND_ROADMAP.md](./SHARING_AND_ROADMAP.md).


## تصوير المستند وتحويله مباشرة إلى PDF

أُضيف خيار **تصوير مستند** في شريط الأدوات:
- يطلب فتح كاميرا الجهاز الخلفية على المتصفحات الداعمة عبر `capture=environment`؛ وقد يعرض المتصفح منتقي الصور بدل الكاميرا إذا لم يدعم الالتقاط المباشر.
- التقط صفحة، ثم التقط صفحات أخرى بالتتابع. اضغط **إنهاء المسح** لتحويل جميع الصفحات الملتقطة إلى ملف PDF واحد وتنزيله.
- تُضاف الصفحات أيضًا إلى مساحة التحرير الحالية، وتُنشأ نسخة PDF مستقلة للمسح.
- قبل الإنهاء يمكنك اختيار تحسين الألوان (تمديد التباين محليًا)، أو الرمادي، أو الأبيض والأسود (عتبة Otsu)، أو الصورة الأصلية. تتم المعالجة على Canvas داخل المتصفح.
- التحويل والتحسين محليان باستخدام Canvas وPDF-Lib؛ لا تُرسل الصور إلى الخادم.
- يتضمن الإصدار محرك OpenCV.js يُحمّل عند طلب المسح فقط: يحاول اكتشاف حدود الورقة تلقائيًا، ثم يعرض أربع نقاط قابلة للسحب لمراجعتها وتصحيحها يدويًا، وبعدها ينفّذ قصًّا رباعيًّا وتصحيحًا للمنظور محليًا.
- بعد ضبط صفحات المسح، تظهر شاشة مراجعة قبل إنشاء PDF: معاينة مصغّرة لكل صفحة، تغيير ترتيبها للأعلى/الأسفل، تدويرها 90 درجة، وحذف الصفحات غير المطلوبة. لا يُنشأ الملف حتى يعتمد المستخدم الترتيب النهائي.
- يحتاج تحميل OpenCV.js إلى اتصال بالإنترنت عند أول استخدام. إذا تعذّر تحميله، يبقى تحويل الصور الأصلية إلى PDF متاحًا دون القص الذكي. ويمكن للمستخدم اختيار «استخدام الأصل» من شاشة ضبط كل صفحة.
- يتطلب الوصول إلى الكاميرا سياقًا آمنًا مثل HTTPS أو localhost. كشف الحواف آليًّا تقديري وليس مضمونًا مع الخلفيات المعقدة أو الورق منخفض التباين؛ راجع النقاط يدويًا، واختبر Safari على iPhone وChrome على Android قبل اعتماد الميزة للإنتاج.

## قياس جودة OCR العربي

أُضيف [مختبر OCR](./docs/OCR_BENCHMARK.md) لمقارنة Tesseract وPaddleOCR وHybrid باستخدام النص المرجعي، وقياس CER وWER والزمن. جهّز مجموعة صور اصطناعية أو مصرحًا بها، ثم شغّل:

```bash
python tools/ocr_benchmark.py --manifest benchmarks/my-arabic-set/manifest.json
```

قالب إعداد العينات في [manifest.example.json](./benchmarks/manifest.example.json). لا توجد نتائج دقة مُعلنة قبل إضافة صور مرجعية وتشغيل المختبر فعليًا في بيئة تحتوي على المحركات المطلوبة.

### تحويل ملفات Office إلى PDF عبر Gotenberg (تكامل اختياري)

أضيف المسار `POST /api/convert/office-to-pdf` لتحويل ملفات Word وExcel وPowerPoint وOpenDocument باستخدام Gotenberg 9 ومحرك LibreOffice. التكامل **غير مفعّل افتراضيًا** ولا يؤثر في النشر المجاني الحالي.

لتفعيله، شغّل خدمة Gotenberg مستقلة وموثوقة، ثم اضبط المتغير السري/البيئي `GOTENBERG_URL` على عنوانها الداخلي أو الخاص. لا تضع عنوان خدمة عامة غير موثوقة. يعرض `/api/health` حالة توفر التحويل. يطبق المسار حدود الرفع ومعدل الطلبات والتزامن، ويتحقق من أن الناتج PDF قبل إرساله.

- نقطة التحويل: `POST /api/convert/office-to-pdf` مع حقل multipart باسم `file`.
- الامتدادات المقبولة: DOC/DOCX/ODT/RTF/TXT/XLS/XLSX/ODS/PPT/PPTX/ODP.
- حجم الناتج الافتراضي الأقصى: `MAX_CONVERTED_MB=40`.
- الخدمة الخارجية لا تُضاف إلى Render Free؛ تشغيل Gotenberg يحتاج موارد مستقلة ومراجعة إعدادات الشبكة والخصوصية.
- لا نعلن الميزة متاحة للمستخدم النهائي قبل إعداد Gotenberg وإجراء اختبار تحويل فعلي على ملفات عربية.

## إعداد الخادم الحالي

تم ضبط الواجهة في `config.js` للاتصال بالخادم `https://got-pdf.onrender.com`. يعتمد ملف `render.yaml` الحالي على الخطة المجانية و`Dockerfile.free`، لذلك يستخدم الخادم Tesseract للعربية والإنجليزية، مع حد افتراضي قدره 10 MB وخمس صفحات PDF وDPI بقيمة 180. لا تستخدم هذه النسخة PaddleOCR الهجين على الخادم. عند تعذر اتصال Render، تحاول الواجهة الرجوع إلى OCR المحلي في المتصفح.

> لم يتم تأكيد استجابة الخادم الحية في وقت هذا التعديل؛ يجب اختبار `/api/health` ورفع ملف تجريبي قبل الاعتماد على الخدمة.

## نشر واجهة المحرر على GitHub Pages

1. افتح المستودع في GitHub.
2. انتقل إلى **Settings → Pages**.
3. في **Build and deployment** اختر **Deploy from a branch**.
4. اختر الفرع `main` والمجلد `/(root)` ثم اضغط **Save**.
5. انتظر اكتمال النشر. رابط المشروع المتوقع:
   `https://abr1404abr1404-afk.github.io/Got-pdf/`

إذا كنت تستخدم نطاقًا مخصصًا، استخدم نطاقك بدل الرابط المتوقع أعلاه.

## نشر خادم OCR على Render

ملف `render.yaml` مضبوط لبناء Docker من جذر المستودع؛ لا تنقل الملفات إلى مجلد backend.

1. أنشئ حسابًا أو سجّل الدخول إلى Render.
2. اختر **New → Blueprint** واربط مستودع `Got-pdf`.
3. راجع الخدمة `alfalqi-pdf-ocr` ثم ابدأ النشر.
4. بعد نجاح النشر افتح عنوان الخدمة وأضف المسار `/api/health`. يجب أن يعرض ردًا JSON يتضمن `"ok": true`.

قد يستغرق تنزيل نماذج PaddleOCR وتهيئتها وقتًا في أول تشغيل. يحتاج الخادم إلى ذاكرة ومعالج مناسبين؛ إذا فشل البناء أو نفدت الذاكرة، راجع سجل البناء والتشغيل في Render قبل تغيير إصدارات المكتبات.

### متغيرات البيئة

يحدد `render.yaml` القيم الافتراضية التالية:

- `MAX_UPLOAD_MB=25`
- `MAX_PDF_PAGES=12`
- `OCR_DPI=240`
- `OCR_MODE=hybrid`
- `CORS_ORIGINS=https://abr1404abr1404-afk.github.io`
- `OPENAI_API_KEY` — مفتاح سري اختياري يُضاف من لوحة Render فقط، ولا يُحفظ في GitHub.
- `OPENAI_MODEL=gpt-4.1-mini` — النموذج الافتراضي للمساعد.

إذا نشرت الواجهة على نطاق آخر، حدّث `CORS_ORIGINS` في إعدادات خدمة Render ليحتوي على أصل الموقع فقط (scheme + hostname، دون مسار المشروع).

## ربط الواجهة بخادم OCR

بعد أن تصبح خدمة Render جاهزة، انسخ عنوانها الأساسي بصيغة HTTPS، ثم افتح `config.js` وعدّل القيمة التالية دون شرطة مائلة في النهاية:

```js
window.ALFALQI_API_BASE = "https://YOUR-SERVICE.onrender.com";
```

استبدل `YOUR-SERVICE` بعنوان خدمتك الفعلي، ثم احفظ التعديل وارفعه إلى GitHub. لا تضع عنوانًا تجريبيًا؛ اترك القيمة فارغة إلى أن تحصل على عنوان الخدمة الحقيقي.

عندما تكون القيمة فارغة، تستخدم الواجهة محرك OCR المحلي في المتصفح. وعندما تُضبط على عنوان الخادم، تحاول استخدام خادم OCR أولًا ثم تعود إلى المحرك المحلي إذا تعذر الاتصال. يستخدم ضغط PDF المحلي تحسينًا آمنًا داخل المتصفح، بينما يتيح الخادم ضغطًا إضافيًا بلا فقد جودة بعد موافقة منفصلة من المستخدم.

### تفعيل مساعد المستندات الذكي

1. أضف `OPENAI_API_KEY` في **Render → الخدمة → Environment** كمتغير سري. لا تضع المفتاح في `config.js` أو GitHub ولا ترسله داخل المحادثات.
2. اترك `OPENAI_MODEL` على `gpt-4.1-mini` أو اختر نموذجًا متاحًا لحساب مزود الخدمة.
3. بعد إعادة نشر الخادم، تأكد أن `/api/health` يعرض `ai_available: true`.
4. اضبط `ALFALQI_API_BASE` في `config.js` على عنوان خادم Render الفعلي.

يستخرج المتصفح نص الصفحات محليًا. لا يُرسل النص إلى المساعد إلا بعد تفعيل مربع الموافقة والضغط على زر التحليل. لا يُرفع ملف PDF نفسه إلى واجهة المساعد. تُرسل النصوص المستخرجة إلى مزود الذكاء الاصطناعي عبر الخادم، وتُطبّق حدود لحجم النص وعدد الطلبات. استخدام مزود الذكاء الاصطناعي قد يترتب عليه رسوم حسب إعدادات حساب مالك المفتاح.

### ضغط PDF

- `POST /api/compress/pdf` — ضغط بنيوي دون فقد جودة باستخدام PyMuPDF، مع إزالة الكائنات غير المستخدمة وضغط التدفقات والصور والخطوط غير المضغوطة.
- يحتفظ الضغط بالنصوص والرسومات المتجهية بدل تحويل الصفحات إلى صور. خيارات الصور: دون فقد، متوازن، أو حجم أصغر؛ الخيارات الأخيرة تعيد ضغط الصور وقد تخفض دقتها قليلًا.
- إذا لم ينتج عن الضغط ملف أصغر، يعيد الخادم النسخة الأصلية بدل تقديم ملف أكبر.
- الواجهة تعرض حجم النسخة قبل الضغط وبعده، ولا تستبدل الملف الأصلي.

## التشغيل المحلي

الأبسط تشغيل الخادم باستخدام Docker من جذر المستودع:

```bash
docker build -t alfalqi-pdf-ocr .
docker run --rm -p 8000:8000 \
  -e CORS_ORIGINS="http://localhost:5500,http://127.0.0.1:5500" \
  alfalqi-pdf-ocr
```

ثم افتح `http://localhost:8000/api/health`.

لتشغيل الواجهة محليًا، استخدم خادم ملفات محليًا (مثل Live Server على المنفذ 5500) بدل فتح `index.html` مباشرة بصيغة `file://`. عند التشغيل المحلي، اضبط `config.js` مؤقتًا على:

```js
window.ALFALQI_API_BASE = "http://localhost:8000";
```

لا تستخدم عنوان HTTP لخادم عام؛ استخدم HTTPS في النشر العام.

## واجهات API

- `GET /api/health` — فحص حالة الخادم.
- `POST /api/ocr/image` — تحليل صورة. حقول multipart: `file` و`language`، والقيم المدعومة للغة: `ara` و`eng` و`ara+eng`.
- `POST /api/ocr/pdf` — تحليل ملف PDF متعدد الصفحات. الحقول: `file` و`language` و`dpi`.
- `POST /api/compress/pdf` — تحسين PDF دون فقد جودة. الحقول: `file` و`level` (`lossless` أو `balanced` أو `small`).
- `POST /api/assistant/chat` — إجابة عن سؤال اعتمادًا على النص المستخرج. JSON: `document_text` و`question`؛ يتطلب `OPENAI_API_KEY` وموافقة المستخدم في الواجهة.
- `POST /api/assistant/extract` — استخراج الأسماء والتواريخ والمبالغ والجهات والمعرّفات من النص المستخرج. JSON: `document_text`؛ يعيد عناصر مع النوع والقيمة ورقم الصفحة ودليل نصي قصير، وتتيح الواجهة تنزيلها CSV بعد الموافقة.

## كيف يعمل OCR الهجين؟

- يستخدم OpenCV تحسينًا معتدلًا للتباين وتقليل الضجيج، ويحاول تصحيح الميلان البسيط عند رصد عدة خطوط أفقية متسقة؛ ويتجنب التدوير عند ضعف الدليل.
- يتجاوز اكتشاف الجداول الصور التي لا تحقق الحد الأدنى المطلوب لمعالجة OpenCV بدلًا من تعطيل طلب OCR.
- يحاول PaddleOCR اكتشاف النص وقراءته.
- يحاول Tesseract قراءة النص أيضًا.
- تُدمج النتائج وتُزال المربعات المتداخلة المتكررة تقريبًا.
- يكتشف الخادم الجداول ذات الحدود الأفقية والعمودية، ويضع النصوص المقروءة داخل خلاياها مع ترتيب RTL للجداول العربية وLTR للإنجليزية.
- يعيد API مصفوفة `tables`، وتتيح الواجهة تصدير الجداول المكتشفة إلى CSV من شريط الصفحة.
- إذا تعذر الوصول إلى الخادم، يمكن للواجهة الرجوع إلى Tesseract.js محليًا.

دعم اللغة العربية في المحركات لا يعني دقة مضمونة؛ يجب قياس CER/WER على ملفات عربية حقيقية قبل إعلان مستوى الدقة.

## الخصوصية والأمان

- عند استخدام OCR المحلي في المتصفح، تتم المعالجة على جهاز المستخدم بعد تحميل مكتبات OCR.
- عند تفعيل خادم OCR، تُرسل الصورة أو صفحة PDF إلى خادم الخدمة لمعالجتها.
- لا ترفع مستندات حساسة إلى خادم عام قبل تحديد سياسة خصوصية، وضبط المصادقة أو الحماية من إساءة الاستخدام، ومراجعة سجلات مزود الاستضافة.
- يطبق الخادم حدًا لحجم الملف وعدد صفحات PDF، لكن ذلك لا يُعد بديلًا عن المصادقة وتحديد معدل الطلبات عند إتاحة API للعامة.

## حدود الإصدار الحالي

- لم يتم تأكيد تشغيل PaddleOCR على خدمة استضافة فعلية بمجرد تعديل ملفات المستودع؛ يجب مراجعة سجلات البناء والتشغيل وتجربة ملفات عربية فعلية.
- كشف الجداول الحالي موجّه للجداول ذات الخطوط الفاصلة الواضحة؛ الجداول بلا حدود أو ذات الخلايا المدمجة أو التخطيط المعقد قد لا تُكتشف بدقة وتحتاج مراجعة بشرية.
- يجب اختبار كشف الجداول وتصحيح الميلان على صور عربية حقيقية ومتنوعة قبل اعتبارهما دقيقين في الاستخدام التجاري؛ اختبارات الوحدة لا تغني عن مجموعة تقييم مرجعية.
- OCR يعيد النص ومربعاته؛ تعديل النص داخل صورة يستبدل المنطقة بطبقة جديدة ولا يستعيد الخط الأصلي تلقائيًا.
- يجب اختبار Safari على iPhone وChrome على Android والمتصفحات المكتبية قبل اعتبار التوافق شاملًا.

## مراجعة نص OCR وتصحيحه

بعد تحليل صفحة، يظهر زر **مراجعة النص** في شريط الصفحة. يفتح محررًا لمراجعة السطور وتصحيح أخطاء التعرّف، مع إمكان نسخ النص أو تنزيله بصيغة TXT. عند حفظ التصحيحات تُستخدم النسخة المصححة في استخراج النص ومساعد المستندات خلال جلسة العمل، بينما يبقى ملف PDF الأصلي دون تعديل. للحفاظ على مواضع السطور فوق الصفحة، يجب إبقاء عدد الأسطر كما هو أثناء التصحيح. لا تُحفظ هذه التصحيحات تلقائيًا بعد إغلاق الجلسة في هذا الإصدار.
