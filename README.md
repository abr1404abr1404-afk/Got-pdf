# الفلقي PDF 2.0 — Web + Hybrid OCR

مشروع تطوير مبني على نسخة محرر الفلقي PDF التي أرسلتِها. يحافظ على الواجهة والوظائف الحالية، ويضيف خادم Python لمعالجة الصور وملفات PDF بمحركين OCR: PaddleOCR وTesseract.

**الحالة:** نسخة تأسيسية قابلة للتشغيل محليًا بعد تثبيت الاعتمادات، وليست خدمة منشورة بعد. راجعي `PLAN.md` للمراحل ومعايير القبول.

## بنية المشروع

```text
alfalqi-pdf-v2/
├── frontend/
│   ├── index.html
│   ├── config.js
│   └── .nojekyll
├── backend/
│   ├── main.py
│   ├── requirements.txt
│   ├── Dockerfile
│   └── .env.example
├── render.yaml
└── PLAN.md
```

## 1) نشر الواجهة على GitHub Pages

ارفعي المشروع كاملًا إلى مستودع GitHub مع الحفاظ على المجلدات. يوجد Workflow في `.github/workflows/pages.yml` ينشر مجلد `frontend/` تلقائيًا. من Settings → Pages اختاري **GitHub Actions** كمصدر النشر. بعد أول Push إلى `main` تابعي Actions حتى يكتمل النشر.

## 2) تشغيل خادم OCR محليًا باستخدام Docker

```bash
cd backend
docker build -t alfalqi-pdf-ocr .
docker run --rm -p 8000:8000 \
  -e CORS_ORIGINS="https://YOUR-USERNAME.github.io,http://localhost:5500" \
  alfalqi-pdf-ocr
```

اختبري `http://localhost:8000/api/health`.

## 3) ربط الواجهة بالخادم

بعد نشر الخادم على عنوان HTTPS، افتحي `frontend/config.js` وضعي العنوان دون `/` في النهاية:

```js
window.ALFALQI_API_BASE = "https://YOUR-OCR-SERVICE.example.com";
```

ارفعي `index.html` و`config.js` إلى GitHub Pages. اضبطي متغير `CORS_ORIGINS` في الخادم ليطابق أصل موقعك، مثل `https://USERNAME.github.io` دون مسار المشروع.

يوجد `render.yaml` كقالب نشر Docker مبدئي. يتطلب PaddlePaddle/PaddleOCR موارد وذاكرة مناسبة؛ قد لا تكفي خطط الاستضافة المجانية. تحققي من متطلبات مزود الاستضافة قبل النشر.

## 4) نقاط API

- `GET /api/health`
- `POST /api/ocr/image` مع حقلي multipart: `file`, `language` (`ara`, `eng`, `ara+eng`).
- `POST /api/ocr/pdf` لمعالجة PDF متعدد الصفحات؛ الحدود الافتراضية 25MB و12 صفحة.

## 5) كيف يعمل OCR الهجين؟

- OpenCV يطبق تحسينًا معتدلًا للتباين وتقليل الضجيج.
- PaddleOCR يحاول اكتشاف وقراءة النص العربي/الإنجليزي.
- Tesseract يحاول قراءة النص ويجمع الكلمات في أسطر.
- تُدمج النتائج وتزال الصناديق المتداخلة المتكررة تقريبًا، مع الاحتفاظ بدرجة الثقة والمحرك.
- إذا تعذر الاتصال بالخادم، تحاول الواجهة استخدام Tesseract.js محليًا.

اللغة العربية مدعومة رسميًا في PaddleOCR بالرمز `ar`، وتوضح وثائقه أن نموذج PP-OCRv5 العربي يشمل العربية والفارسية والأردية وغيرها. <https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/OCR.html>

## الخصوصية والأمان

عند تفعيل خادم OCR، تُرسل الصورة أو صفحة PDF إلى الخادم لمعالجتها. لا تستخدمي مستندات حساسة قبل اختيار استضافة موثوقة وإضافة سياسة خصوصية وحذف وسجلات آمنة. الكود الحالي لا ينشئ تخزينًا دائمًا مقصودًا، لكنه لا يمثل تدقيقًا أمنيًا مكتملًا. قبل نشر API للعامة، أضيفي مصادقة، وتحديد معدل الطلبات، وحماية إساءة الاستخدام.

## حدود الإصدار الأول

- لا توجد دقة OCR مضمونة 100%. يجب قياس CER/WER على مستندات عربية حقيقية قبل ادعاء مستوى دقة.
- OCR يعيد النص ومربعاته؛ أما تعديل النص داخل صورة فيستبدل المنطقة بطبقة جديدة، ولا يستعيد خط الصورة الأصلي تلقائيًا.
- الجداول المعقدة، الخطوط الصغيرة، التصوير المائل، والأختام تحتاج مرحلة فهم تخطيط ومراجعة بشرية.
- توافق واجهة PaddleOCR يتغير بين الإصدارات؛ يجب اختبار Docker فعليًا على مزود الاستضافة، وقد تحتاج بعض خيارات تهيئة المحرك إلى ضبط حسب إصدار PaddleOCR المثبت.
- لا يمكن تأكيد عمل جميع الأجهزة حتى اختبار iPhone Safari وAndroid Chrome وWindows/macOS فعليًا.
